## 三·五、主文档 vs 过程文档

| 类别 | 含义 | 是否参与后续变更 |
|------|------|:----:|
| **主文档（真相源）** | 需求/流程/数据库/机制/原型/规划/拆解 | ✅ 设计变更只改这里 |
| **过程文档** | 复核报告/评审纪要/阶段冻结/修复方案 | ❌ 历史快照，结论已并入主文档 |

> 已融合内容（数据库补全字段、O1~O4 决策等）已写入正式正文，不再有"新增/待办"碎片。**后续所有文档改动记录在《文档变更记录.md》并写明原因**。

## 五、遗忘信息时的定位路径

```
遇到一个"当时是怎么定的"问题？
  → 1. 判断问题属于哪一类：
       · 规则/角色      → 业务逻辑说明.md
       · 状态/流程      → 业务流程图解.md
       · 字段/索引      → 数据库结构说明.md
       · 技术如何实现   → 技术机制预研.md
       · 决策/O1-O4     → 评审问题与待办修复方案.md
  → 2. 若仍有歧义，回读 "文档职责速记"（第四节）确认归属。
  → 3. 记忆"每一份文档一句话职责"，即可快速对应，无需通读全文。
```
