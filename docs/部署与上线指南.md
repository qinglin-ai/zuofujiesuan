## 一、小程序域名部署与「商家转账到零钱」上线指南


> 文档版本：2026-09-21 ｜ 适用：功能已开发完成（阶段一~五 ✅），首次将小程序 + 后端部署到**公网备案域名**并启用微信自动打款

### 〇、部署目标与现状基线

| 项 | 本项目的具体值 | 来源 |
|---|---|---|
| 小程序（兼职端） | 微信原生小程序，请求前缀 `backendBaseUrl` | `miniprogram/app.js:6` |
| 部署域名 | `https://jiesuan.zuofu.info` | `miniprogram/app.js` / 根 `.env` |
| 后端 API | Flask + gunicorn，容器内监听 `5000` | `backend/Dockerfile`（`gunicorn -w 4 -b 0.0.0.0:5000`） |
| 数据库 | MySQL 8 容器 `zuofu_mysql`，库 `zuofu_parttime` | `docker-compose.yml` |
| 管理后台 | Flask 静态托管，入口 `/admin` | `backend/app/__init__.py` |
| 微信支付回调 | `POST /api/pay/transfer/notify` | `backend/app/api/notify.py` |
| 回调地址配置 | `WXPAY_NOTIFY_URL=https://jiesuan.zuofu.info/api/pay/transfer/notify` | `.env` |

**目标**：部署完成后满足微信支付三项硬性要求 —— ①公网 HTTPS 可访问且证书受信任；②域名已完成 ICP 备案且登记在小程序后台；③商户号与小程序 AppID 已绑定、APIv3 凭据齐备，商家转账可正常发起并收到回调。

**关键约束（务必先读）**：

1. **小程序合法域名必须是已备案域名**，且不支持 IP / localhost；未备案域名会被微信公众平台拒绝保存。
2. **微信支付回调地址必须使用受信任 CA 签发的 HTTPS 证书**，自签名证书会导致回调无法送达（回调不来 = 提现单永久 pending）。
3. **回调验签依赖原始请求报文**（`notify.py` 用 `request.get_data()` 取原始 body 做签名校验），因此反向代理**不得改写请求体**、**不得剥离 `Wechatpay-*` 请求头**。
4. **服务器时间必须准确**（微信 API 签名时间戳容差约 5 分钟），时间漂移会导致签名失败（`SIGN_ERROR`）。

### 一、域名注册与 ICP 备案

#### 1.1 前提与选择

- 域名建议与主体（企业/个体工商户）一致注册，并在同一云厂商完成**实名认证**；`.info` 后缀可正常备案。
- **备案只在境内服务器（大陆地域）需要**。若服务器在境外/香港，域名可免备案直接 HTTPS，但**微信小程序「服务器域名」对境内主体要求备案**，且支付回调走境外链路稳定性差。**本项目按「境内服务器 + 主域名备案」执行**。
- **子域名无需单独备案**：只要主域名 `zuofu.info` 已完成网站备案，`jiesuan.zuofu.info` 自动处于备案覆盖范围内，可直接用于小程序域名与支付回调。
- 备案需要该云厂商的**境内云服务器实例（通常要求 ≥3 个月且已付费）**，备案期间域名解析到该服务器的 80/443 可能被云厂商拦截（未备案拦截页），属正常现象。

#### 1.2 备案操作步骤

1. 云厂商控制台进入「备案」→ 新增备案（首次）或「新增网站」（主域名已备案时）。
2. 填写主体信息（营业执照/法人身份证/应急联系电话）、网站信息（网站名称、域名 `zuofu.info`、服务器实例）。
3. 上传证件、完成人脸核验，提交至云厂商初审（约 1 个工作日）。
4. 云厂商初审通过后提交**省通信管理局**终审，期间注意接听核实电话。
5. 备案成功后获取**备案号**（如 `粤ICP备xxxxxxxx号-1`），并在网站底部展示；云厂商域名拦截自动解除。

#### 1.3 验收

```bash
# 备案号查询（工信部）
# 打开 https://beian.miit.gov.cn 输入 zuofu.info 查询，能查到即备案成功
# 域名解析确认
nslookup jiesuan.zuofu.info
```

> **注意**：备案完成前不要配置小程序服务器域名，也不要开启 `WXPAY_ENABLED=1` 做真实转账（回调不通会导致单号异常）。

### 二、服务器环境配置

#### 2.1 基础规格与初始化

推荐 2 核 4G 起（MySQL 8 + gunicorn 4 worker），Ubuntu 22.04 / 24.04 或 Alibaba Cloud Linux。

```bash
# 1) 时区与时间同步（微信签名依赖时间，必须做）
timedatectl set-timezone Asia/Shanghai
timedatectl status
# 建议安装 chrony 并确认同步正常
apt-get update && apt-get install -y chrony nginx
chronyc tracking | grep -E "System time|Leap"

# 2) 磁盘检查（历史上曾因 /data 分区写满导致 MySQL 初始化失败、残留脏数据卷）
df -h
docker system df
```

**磁盘防爆**：`docker-compose.yml` 未对容器日志做限制时，日志会无限增长。部署后追加日志限制（或在 `/etc/docker/daemon.json` 全局配置）：

```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```

改完 `systemctl restart docker`（会重启全部容器，请在业务低峰执行）。

#### 2.2 安装 Docker 与 Compose

```bash
curl -fsSL https://get.docker.com | sh
docker -v && docker compose version
systemctl enable --now docker
```

#### 2.3 防火墙 / 安全组

| 端口 | 用途 | 是否对公网开放 |
|---|---|---|
| 22 | SSH | ✅（建议限制来源 IP） |
| 80 | HTTP（跳转 443 + 证书校验） | ✅ |
| 443 | HTTPS（小程序 API + 支付回调） | ✅ |
| 5001 | 后端容器宿主映射（绑 docker 网关 IP `172.18.0.1:5001`，供容器内 Nginx 经 `host.docker.internal:5001` 反代） | ❌ **不开放** |
| 3306 | MySQL（仅容器内网使用） | ❌ **不开放** |

> `docker-compose.yml` 已按最小开放原则收敛：MySQL **不向宿主机发布 3306**（后端经 compose 网络 `mysql:3306` 访问）；后端映射为 **`"172.18.0.1:5001:5000"`**（容器内仍监听 5000，宿主端口与共用 443 的 Nginx vhost 上游保持一致），对外只暴露 Nginx 的 443。
>
> 该绑定地址**既不能写 `0.0.0.0:5000`**（同宿主其他项目常占用，如 `audio_server`），**也不能写 `127.0.0.1`**（容器内的 Nginx 访问不到宿主回环，必然 502，详见 §3.5）。

### 三、SSL 证书申请与安装

#### 3.1 获取证书（二选一）

**方案 A：云厂商免费 DV 证书（推荐，运维最简单）**

1. 云厂商控制台 →「SSL 证书」→ 申请免费证书 → 绑定 `jiesuan.zuofu.info`（DNS 自动验证）。
2. 签发后下载 **Nginx 格式**，得到 `jiesuan.zuofu.info.crt`（已含中间证书）与 `jiesuan.zuofu.info.key`。
3. **记下到期日**：免费证书有效期已缩短（3 个月 ~ 1 年不等），到期未续会同时打断小程序请求与支付回调。

**方案 B：Let's Encrypt（certbot，自动续期）**

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d jiesuan.zuofu.info     # 自动写入 Nginx 配置并申请证书
certbot renew --dry-run                   # 验证自动续期链路
systemctl list-timers | grep certbot      # 确认续期定时器已注册
```

#### 3.2 安装证书文件

```bash
mkdir -p /etc/nginx/ssl
cp jiesuan.zuofu.info.crt /etc/nginx/ssl/
cp jiesuan.zuofu.info.key /etc/nginx/ssl/
chmod 600 /etc/nginx/ssl/jiesuan.zuofu.info.key
chown -R root:root /etc/nginx/ssl
```

#### 3.3 Nginx 反向代理配置

> 本节适用于「80/443 由宿主 Nginx 持有」的场景。若宿主 80/443 已被其他项目的容器占用（本机实际情况），宿主 Nginx 无法再绑定 443，请直接按 §3.5 在既有容器内新增 vhost。

新建 `/etc/nginx/conf.d/jiesuan.conf`：

```nginx
# HTTP 全量跳转 HTTPS（备案校验、证书续期会用到 80）
server {
    listen 80;
    server_name jiesuan.zuofu.info;
    location /.well-known/acme-challenge/ { root /var/www/html; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl;
    server_name jiesuan.zuofu.info;

    ssl_certificate     /etc/nginx/ssl/jiesuan.zuofu.info.crt;
    ssl_certificate_key /etc/nginx/ssl/jiesuan.zuofu.info.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;
    ssl_session_cache   shared:SSL:10m;

    access_log /var/log/nginx/zuofu.access.log;
    error_log  /var/log/nginx/zuofu.error.log;

    # 请求体上限（正常业务报文很小，10m 足够）
    client_max_body_size 10m;

    location / {
        proxy_pass         http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   Connection        "";
        proxy_read_timeout 30s;
        proxy_send_timeout 30s;
    }
}
```

**回调相关三条铁律（配置时逐条核对）**：

1. **不要启用任何改写请求体的模块**：不要给 `/api/pay/transfer/notify` 挂 `sub_filter`、`body_filter_by_lua` 等；Flask 侧是按**原始报文字节**做验签的。
2. **不要剥离 `Wechatpay-*` 请求头**：微信头部为连字符命名（`Wechatpay-Signature`/`Wechatpay-Serial`/`Wechatpay-Timestamp`/`Wechatpay-Nonce`），Nginx 默认原样透传，**不要添加 `proxy_set_header` 覆盖它们**。
3. **回调必须回 200**：当前实现成功时返回 `{"code":"SUCCESS"}` + 200，失败返回 4xx/5xx（微信会按其重试策略重推），无需在 Nginx 层做任何拦截或返回改写。

生效与校验：

```bash
nginx -t && systemctl reload nginx
systemctl enable nginx
```

#### 3.4 验收

```bash
# 证书有效期与签发机构（必须为受信任 CA，不能是自签名）
echo | openssl s_client -connect jiesuan.zuofu.info:443 -servername jiesuan.zuofu.info 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates

# 证书链完整性（应能验证到根 CA，输出 "Verify return code: 0 (ok)"）
echo | openssl s_client -connect jiesuan.zuofu.info:443 -servername jiesuan.zuofu.info 2>&1 | grep -E "Verify return code"

# HTTP 自动跳转
curl -sI http://jiesuan.zuofu.info | head -3     # 期望 301 Location: https://...

# 后端健康检查穿透验证
curl -s https://jiesuan.zuofu.info/api/health/ping
curl -s https://jiesuan.zuofu.info/api/health/db
```

> 建议用**手机 4G**（非办公网）再访问一次，排除内网 DNS/代理干扰。

#### 3.5 80/443 已被其他项目占用时（多项目共存）

若 `docker ps` 显示 80/443 已由其他容器占用（如另一项目的 `*-frontend` Nginx 容器绑定 `0.0.0.0:80/443`），**宿主 Nginx 无法再绑定 443**，需按下列方案之一处理：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 复用现有 Nginx（推荐）** | 在已占用 443 的 Nginx 容器内为本域名新增 `server` 块（`server_name jiesuan.zuofu.info`），反代到本项目后端 | 需能改该容器挂载的 `conf.d` 与证书目录 |
| B. 移交 443 入口 | 把原项目 Nginx 入口改到其他端口，由本项目 Nginx 统一接管 443 并为两个域名做 vhost | 影响另一个线上项目，需停机窗口 |
| C. 使用非 443 端口 | 本项目 Nginx 监听其他端口对外提供 HTTPS | 小程序 `request` 支持带端口，但**微信支付回调对端口较敏感**，不建议 |

**方案 A 的关键点**：容器内的 `127.0.0.1` 指容器自身，所以**后端不能只绑宿主回环**——必须绑定到「该 Nginx 容器可达的宿主地址」，再让 vhost 的 `proxy_pass` 指向它。

```bash
# 1) 查该 Nginx 容器里 host.docker.internal 实际解析到的宿主地址（输出的 IP 就是要绑的地址）
docker exec <nginx容器名> getent hosts host.docker.internal
#    也可查其所在网络的网关：
#    docker inspect <nginx容器名> --format '{{range .NetworkSettings.Networks}}{{$k}} gateway={{$v.Gateway}}{{"\n"}}{{end}}'

# 2) 按该地址改 docker-compose.yml 的 ports（宿主端口与 vhost 上游端口保持一致），例如实际解析为 172.18.0.1：
#    ports:
#      - "172.18.0.1:5001:5000"

# 3) 重建后端并验证容器内可达
docker compose up -d --no-deps backend
docker exec <nginx容器名> curl -s http://host.docker.internal:5001/api/health/ping

# 4) 新增 vhost 后热加载
docker exec <nginx容器名> nginx -t && docker exec <nginx容器名> nginx -s reload
```

**本项目实际案例**：443 由容器 `aiscan-frontend` 持有（`nginx/1.29.x`，网络 `aiscan_default`），其 `jiesuan.zuofu.info` vhost 上游写的是 `http://host.docker.internal:5001`；该容器内 `host.docker.internal` **实际解析为 `172.18.0.1`（宿主 `docker0` 网关，并非默认的 `172.17.0.1`）**，故 compose 端口最终定为 `"172.18.0.1:5001:5000"`，**Nginx 侧一行都不用改**。

两个高频误判信号：

- **公网访问 502 Bad Gateway，而宿主上 `curl` 后端却返回 200**：不是后端故障，而是后端绑定地址对 Nginx 容器不可达（绑了宿主回环，或绑了错误的网关 IP）。
- **`up` 报 `failed to bind host port 172.x.x.x:5001/tcp: cannot assign requested address`**：`ports` 里写的 IP 在该宿主上不存在（网关 IP 写错），用上面第 1 步核准。

**✅ 实测验证结论（2026-09-29）**：上述方案已在本项目服务器上真实落地并验证通过——后端绑定 `172.18.0.1:5001`、Nginx 容器内 `host.docker.internal` → `172.18.0.1`、vhost 上游 `http://host.docker.internal:5001`，公网访问 `https://jiesuan.zuofu.info/api/health/db` 返回正常（DB ok），**Nginx 侧未做任何改动**。后续同环境部署可直接照此绑定，无需再试 `172.17.0.1`。

> §3.3 的三条回调铁律（不改写请求体、不剥离 `Wechatpay-*` 头、回调须 200）在方案 A 下同样适用。

#### 4.2 微信支付证书落位

#### 4.3 准备宿主数据目录并启动服务

MySQL 数据目录采用**宿主绑定挂载**（`/data/zuofujiesuan/mysql`）。首次启动前必须先创建并授权——容器内 MySQL 用户 uid/gid 为 `999`，权限不对会以 `Can't create/write to file` 之类的错误启动失败：

```bash
docker compose down            # 若已启动过，先停，保证 datadir 处于一致状态
df -h /data                    # 确认分区有空间（历史上曾因 /data 写满导致 MySQL 初始化失败）
mkdir -p /data/zuofujiesuan/mysql
chown -R 999:999 /data/zuofujiesuan/mysql

# 若此前部署用的是命名卷，要保留其中数据就先复制过去（必须在容器停止状态下操作）：
```

```bash
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" < /docker-entrypoint-initdb.d/005_users_profile_nullable.sql'
```


### 五、微信支付配置（商户号绑定与 API 密钥）

#### 5.1 商户号与小程序的 AppID 绑定

商户平台 →「产品中心 → AppID 账号管理」→ 关联小程序 AppID，小程序管理员在微信中确认。绑定关系缺失时，发起转账会直接报 `APPID_MCHID_NOT_MATCH`。

#### 5.2 开通「商家转账」产品权限

商户平台 →「产品中心 → 商家转账」→ 申请开通，并选择转账场景（如 `1000` 现金营销）与**场景报备信息**。批复后：

- `WXPAY_TRANSFER_SCENE_ID` 填批复的场景 ID；
- `WXPAY_SCENE_REPORT_INFOS` 的 `info_type` **必须与该场景的枚举值严格一致**，否则发起即 `PARAM_ERROR`（系统按确定性失败转人工，不会换单重试）。

#### 5.3 API 安全凭据

商户平台 →「账户中心 → API 安全」：

| 配置项 | 获取方式 |
|---|---|
| `WXPAY_API_V3_KEY` | 设置 32 位 APIv3 密钥（**设置后不可查看，务必自行留档**） |
| `WXPAY_MCH_SERIAL_NO` | 申请「商户 API 证书」后，从 `apiclient_cert.pem` 提取：`openssl x509 -in apiclient_cert.pem -noout -serial` |
| `WXPAY_MCH_PRIVATE_KEY_PATH` | 证书 zip 解压得到的 `apiclient_key.pem`（无密码 PKCS#8），放入 `backend/certs/` |
| `WXPAY_PLATFORM_PUBLIC_KEY_ID` | 下载「微信支付公钥」后记录的**公钥 ID**，与 `pub_key.pem` 必须成对使用 |

> 「证书登录密码」**仅用于解压官方证书包**，不写入任何配置（程序加载私钥时 `password=None`）。

#### 5.4 回调地址

`WXPAY_NOTIFY_URL=https://jiesuan.zuofu.info/api/pay/transfer/notify`

- 商家转账的 `notify_url` 是**请求参数，无需在商户平台登记**；微信在发起转账时按该地址回调。
- 微信侧要求：**HTTPS + 公网可达 + 受信任 CA 证书 + 域名已备案 + 不能使用 IP + 不能携带查询参数**。

#### 5.5 配置生效与自检

```bash
vim /opt/zuofu/.env          # 写入 5.2~5.4 各项
docker compose up -d         # 修改 .env 或更换证书后必须重建/重启容器才生效
docker compose restart backend

# 协议层自检（请求签名回环 / 姓名加密 / 回调解密 / 防重决策表）
docker compose exec backend python -m flask wxpay-selfcheck
```

`wxpay-selfcheck` 全部 `[OK]` 后，再按《微信支付集成与联调方案.md》执行真实小额转账联调（阶段 2~5）。

### 八、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `up` 报 `Bind for 0.0.0.0:3306 failed: port is already allocated` | 宿主机或**其他项目**的 MySQL 容器已占用 3306 | 本项目不发布 3306（走容器网络），无需抢端口；先 `docker ps --format 'table {{.Names}}\t{{.Ports}}'` 确认占用者，**属于其他业务的一律不要停** |
| `up` 报 `Bind for 0.0.0.0:5000 failed: port is already allocated` | 其他项目的后端容器占用了 `0.0.0.0:5000` | 改用其他宿主端口并与 Nginx vhost 上游对齐（本项目用 5001）。注意 `0.0.0.0:5000` 被占时 `127.0.0.1:5000` 同样绑不上，必须换端口号 |
| `up` 报 `failed to bind host port 172.x.x.x:5001/tcp: cannot assign requested address` | `ports` 里写的 IP 在该宿主上不存在（网关 IP 写错） | 用 `docker exec <nginx容器名> getent hosts host.docker.internal` 查实际地址，按结果改 `ports`（§3.5） |
| 公网接口 **502 Bad Gateway**，但宿主 `curl` 后端返回 200 | 443 上的 Nginx 在容器内，其 `127.0.0.1` 是容器自身；后端只绑了宿主回环地址或错误的网关 IP | 后端改绑该 Nginx 容器可达的 docker 网关 IP，端口与 vhost 上游一致（§3.5） |
| 小程序报「不在以下 request 合法域名列表中」 | 后台未配置 / 未备案 / 域名写成 IP / 版本未重新发布 | 6.1 重新配置并发布版本 |
| 公众平台保存域名失败 | 域名未备案或证书不受信任 | 完成备案；更换为受信任 CA 证书 |
| 浏览器访问域名提示证书错误 | 证书链不完整（缺中间证书）或用了自签名证书 | 使用含中间证书的 `fullchain`，勿用自签名 |
| 发起转账报 `APPID_MCHID_NOT_MATCH` | 商户号未绑定该小程序 AppID | 5.1 完成绑定并由小程序管理员确认 |
| 发起转账报 `PARAM_ERROR` | `WXPAY_TRANSFER_SCENE_ID` 或 `WXPAY_SCENE_REPORT_INFOS` 与已批复场景不一致 | 5.2 按批复内容严格对齐 |
| 微信报签名类错误（`SIGN_ERROR`） | 服务器时间漂移 / 序列号或私钥不匹配 | 校准时间；用 `wxpay-selfcheck` 复核凭据 |
| 提现单一直 `pending`、回调不到 | 回调地址不可达 / 证书过期 / Nginx 拦截或改写报文 / 未重启容器加载新 `.env` | 6.2 三分校验；检查 `docker compose logs backend` 有无回调记录 |
| 回调到达但 401 | `WXPAY_PLATFORM_PUBLIC_KEY_ID` 与 `pub_key.pem` 不配对 | 商户平台重新下载公钥并同步公钥 ID |
| 接口 500 且日志 `1054 Unknown column` | 存量数据目录未执行新增迁移 | 4.4 手动补跑迁移 |
| 接口全部 500 / 后台白屏 | MySQL 容器不健康（多为磁盘写满导致初始化失败） | 清理磁盘、必要时停止容器后清空 `/data/zuofujiesuan/mysql` 重建（见历史处置经验） |
| `/admin` 打开是裸 HTML、css/js 404 | 静态资源走了默认 `/static/*`，而既有 Nginx 只反代 `/api/`、`/admin` 前缀，其余落到既有 Next.js 上游 | 静态资源必须挂 `/admin/static/*`；`curl -I` 若见 `X-Powered-By: Next.js` 即为此症（见 §2.1 `backend/app/__init__.py`） |
| 第 2 个用户微信登录报 500 | `users.phone` 唯一索引 + 登录建档写空串 `''` | 补跑 `005_users_profile_nullable.sql`（§4.4），建档写 NULL |
| 容器日志占满磁盘 | 未限制 Docker 日志大小 | 配置 `max-size`/`max-file` 并重启 Docker |

### 九、安全规范要点（微信支付侧要求）

1. **凭据只在 `.env`**：`WX_APPID`、`WX_SECRET`、`JWT_SECRET`、`WX_MCHID`、`WXPAY_API_V3_KEY` 等不得出现在代码、日志或版本库中；`.env` 权限 600。
2. **私钥最小暴露**：`apiclient_key.pem` 权限 600，仅容器只读挂载；`certs/` 已被 `.gitignore` 忽略。
3. **端口最小开放**：仅 443（及 80 跳转）对外，5001（绑 docker 网关 IP）/3306（容器内网）不对公网开放（见 2.3）。
4. **回调安全**：回调端点不依赖登录态，安全性由微信签名 + 公钥 ID 比对保证；生产**禁止**关闭验签逻辑。
5. **数据可追溯**：每笔转账的 `out_bill_no` 均可在商户平台「商家转账」查询核对；上线首周建议逐笔对账。
6. **回滚能力**：一旦联调或线上出现异常，置 `WXPAY_ENABLED=0` 并 `docker compose restart backend` 即回退半自动流程（管理后台人工「确认到账」），不影响既有数据。

### 六、风险提示

1. **隐私保护指引未通过 = 提审必驳回**：代码侧的协议与勾选只是必要条件，公众平台申报未完成仍会因隐私合规被拒。
2. **协议主体信息必须真实**：《用户服务协议》《隐私政策》中的运营主体名称、联系方式须与备案主体一致，否则可能被认定信息不实。
3. **规则展示必须与实现一致**：如后续调整每日提现次数（`WITHDRAW_DAILY_MAX`）或到账说明，须同步更新提现页文案、《用户服务协议》《业务说明.md》，避免"页面写的和做的不一致"再次被驳回。
4. **撤回同意路径**：用户可通过《隐私政策》载明的联系方式申请撤回授权与注销账号，需保证该联系方式真实可用（可接入客服或运营邮箱）。
