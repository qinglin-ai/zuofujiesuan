# 左辅云创 · 兼职人员管理小程序 需求清单（T1-1 交付物）

> 阶段一 T1-1「需求调研与角色确认」产出。本文档冻结**角色定义、功能范围与非功能需求**，作为后续 T1-2 流程梳理、T1-3 数据库设计的需求依据。
> 范围决策（已确认）：独立 H5 管理后台；外部作业/质检系统已成型仅做对接；微信支付未做需本期建设；准入考试采用人工审批判定；本期全功能一次性交付。

---

## 一、角色定义（冻结）

| 角色 | 名称 | 职责范围 | 使用端 |
|------|------|----------|--------|
| worker | 兼职人员 | 注册、考试准入、浏览/领取任务、提交作业、查看数据与佣金、申请提现、接收公告 | 小程序端 |
| admin | 管理员兼财务 | 注册审批、任务创建/分配、外部核验回写、能力评级（人工）、台账对账导出、违规处罚、提现回写确认、公告管理 | H5 管理后台 |

> 三角色已并为「admin 兼财务」，角色职责与本系统资金/财务闭环一致。

## 二、功能需求清单

### A. 用户与账号（worker + admin）

| 编号 | 需求 | 说明 |
|------|------|------|
| A1 | 微信登录 | code → openid → 云函数鉴权，身份识别以 `_openid` 为准 |
| A2 | 实名注册 | 手机号 + 真实姓名，提交后状态为「待审批」 |
| A3 | 注册审批 | admin 审批通过/驳回，通过后方可接单 |
| A4 | 账号资格管理 | admin 可封禁/解封（独立于审批） |
| A5 | 收款账户绑定 | 提现前需绑定银行卡，未绑定不可提现 |
| A6 | 后台账号鉴权 | H5 后台 admin 登录与角色校验 |

### B. 能力认证与考试（人工审批判定）

| 编号 | 需求 | 说明 |
|------|------|------|
| B1 | 人工准入评定 | 考试判定由 admin 人工审批（examPassed），绑定「任务 × 标注类型」 |
| B2 | 能力等级评定 | admin 评定 junior / middle / senior 等级 |
| B3 | 质量指标维护 | 维护该任务该类型的质检通过率（passRate） |

### C. 任务与作业（核心链路）

| 编号 | 需求 | 说明 |
|------|------|------|
| C1 | 任务创建 | admin 设置：任务名、标注类型、quantity、unitPrice、难度、requireLevel、totalPeople、deadline、forbiddenItems、样例 |
| C2 | 任务浏览 | worker 按开启状态/标注类型浏览可用任务 |
| C3 | 任务领取 | 校验通过后领取，**并发防超领**（事务 + 唯一索引 + 条件自增）；满足条件即分配 |
| C4 | 作业提交 | worker 在外部任务系统完成作业后，本系统将 assignment 置为 submitted |
| C5 | 外部核验回写 | admin 在外部系统核验后回写结果（pass/reject）至本系统 |
| C6 | 任务关闭 | 到期或 admin 手动关闭，未领取名额失效，已领取继续核验 |

### D. 资金链路（最敏感）

| 编号 | 需求 | 说明 |
|------|------|------|
| D1 | 佣金结算 | 核验通过即入账，金额 = 单价 unitPrice，**幂等防重复**（assignmentId 唯一索引） |
| D2 | 余额管理 | 可提现余额原子增减，流水与余额一致（事务） |
| D3 | 提现申请 | 校验余额充足且已绑卡，内免二次审核，扣减余额写 pending 记录 |
| D4 | 提现回写 | 到账后置为 paid（微信支付）。
| D4-1 | 自动回写 | 对接微信支付回调/轮询自动置 paid |
| D4-2 | 半自动回写 | 财务在后台「确认到账」置 paid（作为自动不可用的兜底） |
| D5 | 台账/对账导出 | 按日聚合佣金流水 + 提现记录导出报表，可追溯 |
| D6 | 微信支付开通 | 微信支付能力本期接入（预留企业打款能力） |

### E. 辅助功能

| 编号 | 需求 | 说明 |
|------|------|------|
| E1 | 违规与黑名单 | admin 记录处罚（警告/停派/封禁），用于评估与禁入 |
| E2 | 公告管理 | 公告/流程/项目动态/FAQ，admin 发布，worker 查看 |

## 三、非功能需求

| 编号 | 类型 | 需求 |
|------|------|------|
| N1 | 资金安全 | 资金与并发逻辑仅通过云函数执行，事务保证流水/余额一致 |
| N2 | 并发正确性 | 任务领取不超领；同一人一任务仅可领取一次 |
| N3 | 幂等性 | 同一作业佣金只入账一次；提现回写不重复 |
| N4 | 权限隔离 | 各集合默认仅创建者可读写；balances/commissions/withdrawals 仅云函数可写 |
| N5 | 可追溯性 | 外部核验留存 externalRefNo 可跨系统回查；资金流可对账 |
| N6 | 性能 | 领取高并发场景下原子操作，避免锁竞争 |
| N7 | 稳定性 | 支付回调失败可重试/人工兜底，保证状态闭环 |

| 项 | 状态 | 说明 |
|----|------|------|

| 微信支付 | 本期建设 | 提现自动回写依赖，需 D6 开通 |

## 五、开放项决策（O1~O4 已收敛）

| 编号 | 开放项 | 决策 | 落地实现 |
|------|--------|------|----------|
| O1 | 台账/对账导出的格式与字段口径 | 固定 Excel 模板 + 字段口径清单 | T4-5 按模板编码，含佣金列/提现列/汇总行 |
| O2 | 违规处罚（封禁）对在途作业与已有余额 | 不影响已获得资金 | 待核验作业继续结算，已入账佣金仍可提现，仅禁止后续领取 |
| O3 | 微信支付打款方式 | 企业付款到零钱 | T4-6 按此实现自动回写；需商户开通对应权限 |
| O4 | 公告的定向范围 | 支持定向投递 | 发布时指定：全员 / 仅 worker / 仅 admin / 按能力等级 |
