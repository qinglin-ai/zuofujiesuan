### 三、补全建议（收敛项）

#### 3.1 certifications 增加「评审人 / 评审时间」（人工准入判定落地）
人工考试由 admin 审定，需留痕以便追溯。
- 新增字段：`reviewedBy`（评审 admin id）、`reviewTime`（评审时间，`db.serverDate()`）
- 说明：现有 `examPassed` / `level` 由 admin 写入，补操作者与时间即可闭环。

#### 3.2 withdrawals 增加「支付单号 / 到账回写来源」（微信支付接入落地）
自动回写依赖微信支付，需记录外部单号便于对账。
- 新增字段：`payRefNo`（微信支付单号/商户单号，可选）、`paidSource`（auto 自动回调 / manual 半自动确认）
- 说明：`status=paid` 时填写；与 E7 半自动兜底对应，`paidSource` 区分回写路径。

#### 3.3 commissions 明确「结算周期粒度」与唯一约束范围
- 保持 `settleDate` 记录到日；唯一幂等键为 `assignmentId`（一个作业仅入账一次），不做按天去重。
- 说明：一个作业对应一条佣金，`assignmentId` 唯一即保证同一作业不重复结算（E5）。

#### 3.4 tasks 补 `unitPrice` 语义注释
- `unitPrice` 为单价（每件作业的价格）；佣金 = 提交数量 × unitPrice（本次周期佣金），`assignmentId` 唯一保证一个任务只结算一次。

---

### 四、复核结论

1. **现有数据库结构可复用**，集合划分、状态字段、索引设计均与冻结状态机一致。
2. **需纳入基线 3 处字段补全**：
   - `certifications.reviewedBy / reviewTime`
   - `withdrawals.payRefNo / paidSource`
   - （§3.3/3.4 为注释级收敛，不改结构）
3. **无需新增集合**；微信支付以字段补全承接，不引入支付独立集合。

> 建议将 §三 补全合并回《数据库结构说明.md》，保持单一结构源，供阶段二/三实现直接采用。

### 二、跨阶段待办修复/决策（O1~O4，已收敛）

#### O1 台账/对账导出的格式与字段口径 —— 固定 Excel 模板
- **模板结构**（3 个 Sheet）：
  1. **佣金台账**：openid、真实姓名、settleDate、taskId、taskName、assignmentId、单价金额、externalRefNo
  2. **提现流水**：openid、真实姓名、applyTime、金额、收款账户快照、status、paidTime、payRefNo
  3. **汇总页**：累计入账佣金、累计已提、当前可提现余额、按日汇总表
- **聚合口径**：佣金按 `settleDate`（入账日）按日聚合；提现按 `applyTime` 按日聚合
- **导出**：支持日期范围筛选，T4-5 按模板编码

#### O2 违规处罚对在途作业与余额 —— 不影响已获得资金
- 封禁（status=blocked）后：**禁止后续领取**新任务
- **在途作业**：已提交待核验的继续按正常核验流程结算（不因封禁作废）
- **已有余额**：已入账佣金仍可正常提现，不冻结
- 实现：`blocked` 只在领取入口（S2）做拦截，不干预既有结算与提现链路

#### O3 提现到账方式 —— 企业付款到零钱
- 通道：微信**企业付款到零钱**，实时到账，回调/轮询自动化置 `withdrawals.status=paid`
- 前提：商户号需开通企业付款/现金营销权限
- 回写实现：优先自动回调，失败保留 pending 重试 + 后台人工确认兜底（`paidSource=auto/manual` 区分）
- 补充：需绑定收款账户（openid 接收方），未绑卡不可提现

#### O4 公告定向范围 —— 支持定向投递
- notices 增加投递范围字段：`target`（`all` 全员 / `worker` 仅兼职 / `admin` 仅后台 / 或按能力等级）
- 兼职端/后台按 `target` 过滤拉取，实现定向展示
- （本项需在数据库补 `target` 字段，纳入阶段五 T5-7 实现）
