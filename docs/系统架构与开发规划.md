# 左辅云创 · 兼职人员管理小程序 系统架构与开发规划

> 本文档在《业务逻辑说明.md》《数据库结构说明.md》基础上，从**整体架构、开发周期、开发阶段**三个维度对系统进行规划，作为项目从设计到落地的总体路线图。
> 技术底座：**前后端分离**。前端为微信原生小程序（界面展示 + 用户交互）；后端为独立的云服务端（Python Flask + MySQL），以 REST API 对外提供服务。涉及资金与并发安全的逻辑必须由后端服务承载，并配合数据库事务 / 唯一索引兜底。

---

## 一、系统整体架构

### 1.1 架构总览

系统采用**前后端分离**架构：前端小程序只负责界面展示与用户交互（数据经后端 API 获取/提交），全部核心业务逻辑、数据持久化与资金/并发安全收敛到后端云服务端。前端不直连数据库，无业务数据访问权限。

```
┌──────────────────────────────────────────────────────────────┐
│ 前端（小程序端，界面 + 交互）                                  │
│  ┌───────────────┐   ┌────────────────┐                     │
│  │ 兼职人员端小程序 │   │ 管理后台(H5/小程序端)                 │
│  │ 浏览/领取/提交/  │   │ 审批/建单/核验/对账/处罚               │
│  │ 查余额/提现     │   │               │                     │
│  └───────┬───────┘   └───────┬────────┘                     │
│          │   wx.request (HTTPS + Token 鉴权)                 │
├──────────┼──────────────────────────────────────────────────┤
│  接入层 / 反向代理（Nginx，HTTPS / 负载 / 静态托管）            │
├──────────┼──────────────────────────────────────────────────┤
│ 后端服务（云服务端：Python Flask，承载全部核心业务逻辑）        │
│  认证鉴权(JWT) │ 业务API │ 并发控制 │ 幂等处理 │ 事务管理 │对账 │
│  注册审批  /  能力认证  /  任务派发  /  作业提交  /  佣金结算 / 提现 │
│  （SQLAlchemy ORM，事务由连接会话管理）                        │
├──────────┼──────────────────────────────────────────────────┤
│ 数据层（MySQL）                                               │
│  表：users/balances/certifications/tasks/assignments/        │
│       quality_checks/commissions/withdrawals/violations/     │
│       notices  （详见《数据库结构说明.md》，集合已映射为关系表）│
├──────────┼──────────────────────────────────────────────────┤
│ 外部系统（专门任务系统 / 微信支付）                             │
│  作业提交与质检判定在外部系统；本系统仅回写结果与结算资金         │
└──────────┴──────────────────────────────────────────────────┘
```

### 1.2 分端职责划分

| 端 | 职责 | 说明 |
|----|------|------|
| 兼职人员端（小程序） | 浏览/领取任务、提交作业、查看数据与佣金、申请提现、参加考试 | 仅负责界面与交互；数据均由后端 API 返回 |
| 管理后台（前端） | 注册审批、任务创建/分配、外部核验回写、能力评级、台账对账导出、违规处罚 | admin 专属入口，操作指令经后端 API，后端校验角色 |
| 后端服务（Flask） | 认证鉴权、全部核心业务逻辑、事务/幂等/并发控制 | 涉及资金与并发的逻辑唯一承载方；对前端封闭数据库 |
| MySQL | 业务数据持久化（关系型） | 唯一约束/索引兜底并发与幂等 |
| 前端不直连 | 无数据库访问能力 | 数据只能经后端 API 读写，杜绝客户端越权 |
| 外部任务系统 | 作业提交、质检判定 | 本系统的数据/资金依据来源 |

### 1.3 关键架构约束（安全 / 资金 / 并发）

1. **资金安全**：佣金入账、提现扣减必须由后端在**同一事务**内完成，"流水与余额一致"。
2. **并发防超领**：`claimedCount` 由后端用**原子条件 UPDATE**（`< totalPeople` 时 +1）+ assignments 复合唯一索引 `(_openid, taskId)` 双保险。
3. **结算幂等**：`commissions.assignment_id` 唯一索引，防止重复结算。
4. **权限隔离（前后端分离）**：前端无数据库写权限；后端通过鉴权层校验每个请求的身份与角色（`role == admin` 才允许敏感操作），并对越权请求返回 403（详见《技术机制预研.md》）。
5. **数据与系统解耦**：本系统不存作业素材图，仅回写外部核验结果（`quality_checks.external_ref_no` 用于跨系统追溯）。

## 二、开发周期规划

### 2.1 总体周期与阶段

| 阶段 | 名称 | 周期占比 | 里程碑 | 输出物 |
|------|------|:----:|------|--------|
| 一 | 需求分析与设计 | 15% | 需求冻结、架构评审通过 | PRD、数据库设计、原型 |
| 二 | 基础设施建设 | 10% | Flask 后端 + 小程序前端骨架可运行、前后端可互通 | 项目脚手架、CI/CD、登录链路、MySQL 迁移脚本 |
| 三 | 核心业务开发 | 25% | 任务全生命周期跑通（建单→领取→提交→核验→结算） | 后端 API + 前端核心功能 |
| 四 | 资金链路开发 | 20% | 资金链路联调通过（入账→提现→回写→对账） | 佣金结算、提现、对账模块 |
| 五 | 管理后台与辅助功能 | 15% | 管理后台功能完整、考试/违规/公告上线 | 管理后台、辅助功能 |
| 六 | 测试与安全加固 | 10% | 并发/幂等/权限测试通过，安全审查完成 | 测试报告、安全扫描报告 |
| 七 | 灰度上线与验收 | 5% | 线上运行稳定、验收通过 | 部署手册、验收报告、运维手册 |

### 2.2 开发周期说明

- 采用**迭代式**推进，阶段三、四为核心，优先保证"任务闭环 + 资金闭环"。
- 关键风险点（并发超领、幂等、提现回写）前置到阶段三、四重点验证，避免后置返工。
- 外部任务系统与微信支付为外部依赖，需在阶段四前完成对接约定，保证联调顺畅。

## 三、开发阶段分解

### 阶段一：需求分析与设计

**目标**：冻结需求，完成可落地设计。
- 明确角色（worker / admin兼财务）与业务规则
- 梳理任务全生命周期（创建→领取→提交→核验→结算→关闭）
- 完成《业务逻辑说明.md》《数据库结构说明.md》，冻结 ER 关系与索引设计
- 关键技术预研：Flask/MySQL 下的事务、原子条件更新、唯一约束、鉴权与权限校验
- 里程碑：**设计评审通过**

### 阶段二：基础设施建设

**目标**：搭建可运行的技术底座。
- 搭建后端服务脚手架（Flask 分层目录、配置管理、数据库连接池、REST API 骨架）
- 搭建前端小程序脚手架（原生小程序目录规范、请求层封装）
- 打通微信登录 → openid → 后端签发的 Token 鉴权链路
- MySQL 表结构迁移脚本（含全部唯一约束/索引，对齐《数据库结构说明.md》）、权限基线
- 建立 CI/CD（Gitee/GitHub Actions）、git 版本管理、日志与监控基础
- 里程碑：**脚手架可运行、前后端可互通**

### 阶段三：核心业务开发

**目标**：跑通任务全生命周期主链路。
- 注册审批（users：pending → approved）
- 能力认证与准入考试（certifications）
- 任务创建 / 领取（tasks、assignments，含并发超领控制）
- 作业提交（assignments.status：claimed → submitted）
- 外部核验结果回写（quality_checks + assignments.status → passed / rejected）
- 里程碑：**任务闭环联调通过**

### 阶段四：资金链路开发

**目标**：打通结算与资金闭环（最敏感阶段）。
- 佣金入账（commissions，幂等 + 事务，availableBalance 原子更新）
- 提现申请与扣减（withdrawals，免审核）
- 提现回写（自动 / 半自动置为 paid，配合微信支付）
- 台账 / 对账导出（按日聚合 commissions + withdrawals）
- 里程碑：**资金闭环联调通过**

### 阶段五：管理后台与辅助功能

**目标**：补齐管理侧与辅助能力。
- 管理后台：审批、建单、核验列表（按 checkedBy 查）、对账导出、违规处罚
- 违规与黑名单（violations）
- 公告 / 流程 / 项目动态 / FAQ（notices）
- 里程碑：**管理后台功能完整**

### 阶段六：测试与安全加固

**目标**：保障质量与安全。
- 并发测试：多用户同时领取不超领、重复结算幂等
- 权限测试：越权读写防护、balances 仅本人可读
- 资金一致性测试：流水与余额一致、异常回滚
- 安全审查：云函数鉴权、敏感操作加固（对照数据库设计第四章）
- 里程碑：**测试通过、安全审查通过**

### 阶段七：灰度上线与验收

**目标**：平稳上线并完成验收交付。
- 小范围灰度 → 监控观察 → 全量上线
- 上线后可并行灰度能力等级与考试准入
- 输出：部署手册、运维手册、验收报告
- 里程碑：**验收通过、上线稳定**

## 五、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 并发超领 / 重复结算 | 资金事故 | 后端原子条件更新 + 事务 + 唯一约束双保险（阶段三、四重点验证） |
| 提现未回写导致状态不符 | 对账困难 | 自动/半自动回写闭环，台账留痕可追溯 |
| 外部任务系统对接延迟 | 链路受阻 | 阶段四前锁定对接约定与接口规范 |
| 后端鉴权配置不当 | 越权风险 | 统一鉴权中间件 + 角色校验双保险，前端不直连数据库 |
| 业务规则变更返工 | 工期风险 | 迭代评审，需求冻结于阶段一 |
